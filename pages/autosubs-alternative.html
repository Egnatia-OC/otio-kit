otio-kit · the file-based editing engine

AutoSubs-style workflows, rebuilt on the path 21.1 didn't touch

DaVinci Resolve 21.1 moved scripting to Studio. Python tools that ran on Free — AutoSubs and tools like it — no longer execute: the menu entries remain, the clicks do nothing. What remains is file import: emit a timeline file (OTIO), import it, done. That is exactly the path otio-kit builds on.

Verified 2026-09-15 (first-party) — on the most restricted target I have tested, Resolve Free 21.1 (Linux)

  • Brief — hand-written or LLM-generated → validated spec → OTIO file → import: cut points at the expected frame positions, transitions and markers intact, no relink dialogs (at 23.976 fps the emitter quantizes to whole frames — about 1.4 frames over a 60 s brief; the 24 fps specimen is exact. Documented in the log). Fidelity log.
  • In one temperature-0 sample on a 60-second, three-track specimen, all four capable models hit 5/5 cut points within ±2 frames (the sub-1B control failed); cost per compiled timeline is a fraction of a cent ($0 on a local model). A baseline, not a general accuracy claim. Benchmark doc + re-runnable harness.
  • Local-first by design: the compiler uploads nothing, and the local-LLM workflow keeps the brief on the machine (cloud LLM use is optional). No credit metering, no watermark. AGPL-3.0 open source.

On the public roadmap (planned, not shipped)

  • Subtitle track emission — FCPXML first (it carries captions natively); OTIO caption import into Resolve is on the public fidelity log, so you can watch the verification happen.
  • Bundled local transcription (whisper-class), so the transcribe → cut → caption pipeline runs on your machine.

Get the engine →

pip install otio-kit (Python 3.10+) — or git clone https://github.com/Egnatia-OC/otio-kit && pip install .
