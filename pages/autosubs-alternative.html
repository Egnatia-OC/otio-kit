otio-kit · the file-based editing engine

AutoSubs-style workflows, rebuilt on the path 21.1 didn't touch

DaVinci Resolve 21.1 moved scripting to Studio. Python tools that ran on Free — AutoSubs and tools like it — no longer execute: the menu entries remain, the clicks do nothing. The path that survives is file import: emit a timeline file (OTIO), import it, done. That is exactly the path otio-kit builds on.

Verified today (first-party) — tested hardest-first, on Resolve Free 21.1 (Linux, the most restricted target)

  • Brief — hand-written or LLM-generated → validated spec → OTIO file → import: frame-accurate cuts, transitions and markers intact, no relink dialogs. Fidelity log.
  • Five-model benchmark on a 60-second, three-track specimen: every capable model hit 5/5 cut points within 2 frames; cost per compiled timeline is a fraction of a cent ($0 on a local model). Benchmark doc + re-runnable harness.
  • Local-first by design: no upload, no credit metering, no watermark. AGPL-3.0 open source.

On the public roadmap (labelled roadmap, not claims)

  • Subtitle track emission — FCPXML first (it carries captions natively); OTIO caption import into Resolve is on the public fidelity log, so you can watch the verification happen.
  • Bundled local transcription (whisper-class), so the transcribe → cut → caption pipeline runs on your machine.
